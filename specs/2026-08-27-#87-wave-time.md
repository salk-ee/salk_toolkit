# Auto wave_time survey-date column (STK PR #87, SIP PR #134)

**Modules:** `salk_toolkit/validation.py`, `salk_toolkit/io/core.py`, `salk_toolkit/io/pipeline.py`,
`salk_toolkit/io/sources.py`; SIP `default_settings.py`, `sampling/population.py`,
`data_quality/blocks.py` (companion PR).

## Goal

Multi-wave datasets need a categorical time field for modeling and plotting, and it was
hand-maintained per project. Each wave's meta now declares when it was collected, and every
annotated load derives an ordered categorical `wave_time` column from those dates
automatically, including when waves are combined under a parent meta.

## Design

**Meta declares the date.** `DataMeta` gains `collection_center` alongside the existing
`collection_start`/`collection_end`. A meta's survey date resolves to `collection_center`,
else the start/end midpoint. Convention (see the `stk-data-annotations` skill): fill all
three; `collection_center` is the *mean of per-row collection dates* (center of mass), since
fielding is usually front-loaded and the midpoint sits late.

**Injection is a pipeline stage.** `_inject_wave_time` runs in `process()` right after
`_inject_files_block`, following the same pattern: a `generated` block named `waves` holding
one ordered categorical column `wave_time`, categories = ISO date labels sorted
chronologically. Per source frame: a frame already carrying the column (a nested annotated
child) keeps its per-row values; a frame without one gets this meta's date as a constant; a
frame with neither, in a load where others have dates, gets NA plus a warning. A load with no
dates anywhere is silently unchanged — the feature is invisible until metas are dated.

**Combining stays chronological.** Multi-file loads reconcile categories via
`_fix_meta_categories`, which appends novel categories in first-seen order.
Injection sorts its own labels; `_sort_wave_time_block` then runs once after the
`_load_data_files` reconciliation to restore the ordered dtype (the reconciliation rebuilds it
unordered), union in any observed value the meta's list lacks (a narrower recast would null whole
waves), and set `hidden = single wave`. That covers `read_and_process_data` combining
already-processed sources without a parent meta. An annotated *parquet* never runs `process()`, so
`_load_data_files` fills its wave date from its own embedded meta.

**Nesting composes.** Each child meta injects its own constant on load; a parent sees
children's columns and only unions + sorts. Dates on the children alone are sufficient; a
parent's own dates apply only to files lacking both column and date. Labels being ISO dates
means metric time is recoverable via `pd.to_datetime` on the category names — there is
deliberately no separate numeric mapping to drift out of sync.

**User columns are never trampled.** A column of that name declared in any non-`generated`
block suppresses injection entirely; a pre-existing user block named `waves` keeps its own
columns and visibility (only the time column is merged in); and values that don't parse as
dates are left alone with a warning rather than crashing the load.

**Knob.** `DataMeta.wave_time: bool` — `false` opts a dataset out. The column name is the fixed
`WAVE_TIME_COL` constant in `io/core.py`, which SIP imports, so neither side re-derives it.

**SIP side** (companion change, based on SIP #133): `wave_time` joins the calibrated
`priors.scale` (0.5, same as the old `t` convention) and `gp_nugget` (0.1) tables, and #133's
`TIME_COLS` pins it to the `rw1` kernel with real day gaps read off the ISO labels — so smoothing
is automatic and a "you forgot to smooth your time axis" advisory would be unreachable.
`generate_population` drops a population source's own `wave_time` unless its values really are
survey waves (a census's collection date is not a wave axis; all-NA counts as "not waves", since
keeping it codes every row to the last wave), then appends the column to `population.randomize`
over the *observed* waves when it is a model input present in `sdf` but absent from the
population — warning as it does, since uniform randomization poststratifies to an average over
waves rather than one wave. `data_quality`'s `ARTIFACT_COLS` gains it so it is not scored as a
survey item.

## Implementation notes

- The `waves` block deliberately does not reuse the `files` block: `files` is hidden whenever
  a single file is loaded, but `wave_time`'s visibility must depend on the number of *waves*
  after combining, which only `_sort_wave_time_block` can decide.
- `hidden` is honored by `group_columns_dict` / the explorer's dimension list, but
  `extract_column_meta` does not filter hidden blocks, so a caller that enumerates `cmeta`
  directly still sees a single-wave `wave_time` (exactly as it already sees `file_code`).
- In the `read_and_process_data` multi-meta path the combined meta is the *last* file's
  ("last file is the basis"): if only the last meta is dateless, the column still lands in the
  concatenated frame but the meta carries no `waves` block, so meta-driven consumers won't see
  it — dating the last wave's meta is what makes the field flow through.
- The auto-`randomize` keys off a step's `inp_cols`, so a column reached only through a
  per-output `inputs: {"add": [...]}` does not get one, and `sample_step_populations` passes no
  `used_cols`, so a step-level `populations` entry declares its own `randomize`. The census drop
  is keyed on the fixed column name rather than the meta, so it still protects those populations.
- STK's version is bumped to 0.9.2 and SIP's floor pin follows, since SIP imports the new
  `WAVE_TIME_COL` constant. SIP's pyright resolves STK from `../salk_toolkit`, so its gate is red
  until STK lands: merge STK first.
- `_user_owns` is what makes rule (d) work in both directions: any block other than our own
  *generated* `waves` block owns its columns, so a hand-written `generated: true` block declaring
  `wave_time` suppresses injection instead of colliding with it.
