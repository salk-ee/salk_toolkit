# Auto wave_time survey-date column (STK PR #87, SIP PR #134)

**Modules:** `salk_toolkit/validation.py`, `salk_toolkit/io/core.py`, `salk_toolkit/io/pipeline.py`,
`salk_toolkit/io/sources.py`; SIP `default_settings.py`, `sampling/population.py`,
`data_quality/blocks.py` (companion PR).

## Goal

Multi-wave datasets need a categorical time field for modeling and plotting, and it was
hand-maintained per project. Each wave's meta now declares when it was collected, and every
annotated load derives an ordered categorical `wave_time` column from those dates
automatically, including when waves are combined under a parent meta.

## Design

**Meta declares the date.** `DataMeta` gains `collection_center` alongside the existing
`collection_start`/`collection_end`. A meta's survey date resolves to `collection_center`,
else the start/end midpoint. Convention (see the `stk-data-annotations` skill): fill all
three; `collection_center` is the *mean of per-row collection dates* (center of mass), since
fielding is usually front-loaded and the midpoint sits late.

**The column rides the existing per-file machinery.** Two things STK already does are reused
rather than paralleled: meta-level facts travel down a load in `ProcessOpts` (as `id_col`
does), and `_load_data_files` stamps per-file constants onto each frame. `_load_meta_sources`
puts the meta's date in `opts.wave_date`; in the per-file loop an annotated source brings its
own date from its embedded meta (a processed child already carries the column; a parquet or a
dateless child gets stamped), and a raw file takes the meta's. The name is **reserved**: a raw
file's own `wave_time` is overwritten, exactly as `file_code`/`file_name` are, while an
annotated source's is kept. That one rule replaces any negotiation with foreign values.

**The block rides `_inject_files_block`.** The generated `files` block already exists so the
stamped provenance columns survive `_build_columns` with explicit ordered categories; a
generated `waves` block is declared beside it the same way, through one shared
`_upsert_generated_block` (which also keeps a user's own block of either name intact -- its
columns and `hidden` are never overridden). Categories are the observed dates sorted
chronologically; `hidden` is set when there is a single wave.

**Combining.** A parent meta or a multi-meta `read_and_process_data` sees children that
already carry the column, so only category reconciliation is involved. Two pre-existing gaps
in that reconciliation are closed for every column, not just this one: `_reconcile_categories`
now keeps the source dtype's `ordered`, and `_fix_meta_categories` takes the (chronological)
dtype order for date-labelled columns instead of appending novel values last. What is left for
`wave_time` specifically is a `hidden` refresh by wave count and a warning naming files the
combine left dateless.

**Knob.** `DataMeta.wave_time: bool` opts a dataset out; a column of that name declared in the
annotation's own blocks suppresses injection. The name is the `WAVE_TIME_COL` constant in
`io/core.py`, exported for SIP. No numeric mapping is stored: ISO-date labels carry metric
time, recoverable via `pd.to_datetime`, so there is no second copy to drift.

**SIP side** (companion change, based on SIP #133): `wave_time` joins the calibrated
`priors.scale` (0.5, same as the old `t` convention) and `gp_nugget` (0.1) tables, and #133's
`TIME_COLS` pins it to the `rw1` kernel with real day gaps read off the ISO labels — so smoothing
is automatic and a "you forgot to smooth your time axis" advisory would be unreachable.
`generate_population` drops a population source's own `wave_time` unless its values really are
survey waves (a census's collection date is not a wave axis; all-NA counts as "not waves", since
keeping it codes every row to the last wave). Randomization stays explicit: a model that uses
`wave_time` as an input must give the population a `randomize` entry for it, and the run fails
naming the column otherwise. `data_quality`'s `ARTIFACT_COLS` gains it so it is not scored as a
survey item.

## Implementation notes

- A center given to both ends of the midpoint formula *is* the midpoint, which is why
  `_collection_date` has no branch for it.
- A single-file load hides `waves` (one wave), and a later combine of several such files must
  flip that back -- the `hidden` refresh in `_load_data_files` is the only wave-specific step in
  the combine path.
- `hidden` is honored by `group_columns_dict` / the explorer's dimension list, but
  `extract_column_meta` does not filter hidden blocks, so a caller that enumerates `cmeta`
  directly still sees a single-wave `wave_time` (exactly as it already sees `file_code`).
- In a multi-meta `read_and_process_data` the combined meta is the *last* file's: if only that
  meta is dateless, the column still lands in the frame but no block describes it. Set
  `wave_time` the same on every meta of a combine.
- STK's version is bumped to 0.9.2 and SIP's floor pin follows, since SIP imports
  `WAVE_TIME_COL`. SIP's pyright resolves STK from `../salk_toolkit`, so its gate is red until
  STK lands: merge STK first.
